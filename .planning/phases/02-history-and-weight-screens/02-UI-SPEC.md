# Phase 2 — UI Design Contract

> Visual and interaction contract for the dedicated History and Weight destinations. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing hand-built Material 3 design system; do not initialize shadcn |
| Preset | Not applicable |
| Component library | Project primitives in `src/components/`; no third-party UI framework |
| Icon library | Existing `lucide-react` dependency |
| Chart library | Existing Recharts dependency with `src/charts/useThemeTokens.js` |
| Font | Self-hosted Manrope Variable with system fallback |

This phase reuses `Card`, `Button`, `TextField`, `Sheet`, `ListItem`, `Chip`, and `StatTile`. Extend a primitive additively only when the screen contract cannot be expressed with its current API. New History and Weight presentation belongs in `src/screens/HistoryScreen.jsx` and `src/screens/WeightScreen.jsx` with colocated CSS. `App.jsx` remains the state, persistence, navigation, Firebase, and callback owner.

No new UI framework, styling dependency, remote registry code, hard-coded screen color, inline-style system, or `!important` override is permitted. The approved Android redesign, Phase 1 UI contract, and current callback behavior are authoritative.

---

## Spacing Scale

Declared values are the Phase 1 scale and remain multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps and compact metadata |
| sm | 8px | Set chips and closely related controls |
| md | 16px | Phone gutters, card padding, field separation |
| lg | 24px | Section separation and sheet groups |
| xl | 32px | Major content breaks |
| 2xl | 48px | Minimum interactive target and generous empty-state spacing |
| 3xl | 64px | Large page-level separation only |

Exceptions: safe-area insets come from the shared shell; chart plotting heights and anatomy-independent media dimensions are not spacing tokens. Existing 12px/20px/40px project tokens may remain inside shared primitives, but new Phase 2 screen composition uses only the declared values above. Interactive controls remain at least 48px by 48px.

## Typography

Use exactly the same four semantic roles as Phase 1. Numeric values use tabular numerals.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 11px | 600 | 1.3 |
| Body | 13.5px | 400 | 1.5 |
| Heading | 23px | 600 | 1.2 |
| Display | 52px | 600 | 1.05 |

Only weights 400 and 600 are introduced by this phase. The Weight headline may use Display; session titles, month headings, chart labels, metadata, field copy, and action labels map to the four roles above. Do not reproduce the legacy 700–900 weight stack or text below 10.5px.

## Color

Color is expressed through the existing semantic tokens so the same contract works in both themes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--surface)` | Screen background and open space |
| Secondary (30%) | `var(--surface-container)` / `var(--surface-container-high)` | Cards, expanded details, sheets, chart surfaces |
| Accent (10%) | `var(--primary)` / filled-control role pair | Primary Add/Save actions, selected/focused state, trend series, small day identity dot |
| Destructive | `var(--error)` / `var(--on-error)` | Delete controls, irreversible confirmation heading/action only |
| Success | `var(--success)` | Successful save feedback only |
| Warning | `var(--warn)` | Recoverable caution only, never routine weight change |

Accent is reserved for the Weight hero value, primary Add/Save controls, focused or selected states, the primary weigh-in series, and the single small day identity dot on a workout card. Weight gain or loss is not intrinsically success, warning, or failure; net change uses neutral `--on-surface`/`--on-surface-variant` text with a signed value. Workout-template rainbow colors remain data but are demoted to the dot and never become card borders or large fills. Recharts receives literal values only through the existing chart-theme adapter, not CSS variables in SVG attributes.

## Information Architecture and Visual Hierarchy

### History destination

1. Screen heading and concise supporting count.
2. Calendar-month groups, newest month first.
3. Within each group, workout cards ordered newest first.
4. A collapsed card shows day identity, local calendar date, exercise/set count, and existing calculated volume when available.
5. Expanding a card reveals every stored exercise, set, tracking-specific result, notes, readiness/details already present in the record, and Edit/Delete actions. Expansion never aggregates away stored details.
6. Export/reset account-level utilities stay in Settings or their already-approved overflow location; they do not return as History footer chrome.

Month headings are sticky only if they do not collide with the shared app bar or obscure keyboard focus; otherwise they remain ordinary semantic headings. Use localized month labels derived from the stored local ISO date without UTC conversion. At most one card should be expanded by default; preserving one explicit expanded card at a time is recommended for the narrow phone column.

### Weight destination

1. Summary hero: latest weight, latest date, signed net change, and weigh-in count.
2. Bodyweight trend card: weigh-in line plus existing seven-day moving-average line, current display unit, concise text summary, and accessible data representation.
3. `Add weigh-in` primary action.
4. Weigh-in history, newest first, with Edit and Delete actions.

The add form does not permanently occupy the top of the page. Add and Edit both open the same focused Material bottom sheet. With fewer than two valid entries, retain the summary/history that exists and replace only the chart plot with its local empty explanation.

## Component and Content Contract

### History groups and workout cards

- Screen landmark: `<section aria-labelledby="history-title">`; visible heading `History`.
- Month groups use an `h2` month/year heading and a list of sessions. The total supporting line uses correct singular/plural copy: `{N} workout` / `{N} workouts`.
- Each card disclosure is a real button with `aria-expanded` and an `aria-controls` relationship to its detail region. The full card header may be tappable only when it retains button semantics, visible focus, and a 48px minimum target.
- Collapsed summary uses the stored day label and emoji where valid; malformed or missing template keys fall back to `Workout` without crashing. Show the date in readable local form while retaining the exact stored date for editing.
- Summary metadata reads `{N} exercises · {N} sets` and adds `{volume} {unit} volume` only when the current calculation produces a meaningful value. Mixed/non-weighted sessions do not receive a fabricated volume.
- Expanded exercises preserve stored order. Each exercise shows its name and set rows/chips using existing tracking semantics: weighted weight × reps plus unit, bodyweight reps, timed seconds, and distance meters. Missing optional fields are omitted, not rendered as misleading zeroes.
- Long names and notes wrap. Sets wrap within the card. No session detail creates page-level horizontal scrolling.
- Actions in the expanded panel are `Edit workout` and `Delete workout`. Delete remains separate from editing.

### Workout edit sheet

- Sheet title: `Edit workout`; supporting date/day context remains visible.
- Edit the stored local date, day/template selection where current behavior supports it, exercise names, tracking-compatible set values, and notes without changing the completed-session record schema.
- Use project `TextField`/select/control patterns with explicit labels. Set controls retain correct numeric input modes and units.
- Primary action: `Save workout`; secondary action: `Discard workout changes`.
- The sheet opens with a copied draft. `Discard workout changes`, Escape, scrim, drag, or browser/Android back discards only that draft and leaves the confirmed session unchanged.
- Validate through the same domain rules used for a completed workout. A failed validation or persistence attempt keeps the sheet open, retains entered values, focuses or associates the first error, and announces recoverable feedback.
- Only a successful persistence callback updates the card and closes the sheet. Focus returns to the invoking `Edit workout` button.

### Weight summary and trend

- Screen landmark: `<section aria-labelledby="weight-title">`; visible heading `Weight`.
- Latest value is the dominant numeral with its display unit adjacent. Supporting values are `Latest · {date}`, `{signed value} {unit} net change`, and `{N} weigh-ins`.
- The display-unit control may reuse the existing lb/kg preference semantics. Switching display units converts presentation only and never rewrites stored entries.
- Trend card heading: `Bodyweight trend`; legend labels: `Weigh-in` and `7-day average`.
- The chart retains the existing chronological weigh-in series and moving-average behavior. Theme changes rerender the chart through `useThemeTokens`; reduced motion disables chart animation.
- Tooltip inspection is an enhancement, not the only representation. Provide a concise summary and an accessible table/details representation containing full date, weigh-in, trend value, and unit.
- Do not imply a health judgment or target direction. Net gain and net loss use neutral language and color.

### Add/edit weigh-in sheet and history

- `Add weigh-in` opens title `Add weigh-in`; editing opens title `Edit weigh-in`.
- Fields are `Weight`, `Unit`, and `Date`. Weight uses decimal input mode; unit options remain lb/kg; date remains a local ISO calendar date.
- Supporting copy for add: `One entry per day. Saving the same date updates that day’s weigh-in.`
- Primary action: `Save weigh-in`. The Add sheet secondary action is `Close add weigh-in`; the Edit sheet secondary action is `Discard weigh-in changes`.
- Edit starts from a copied record. If its date changes, cloud deletion/save coordination remains an `App.jsx` callback concern; the screen only submits the confirmed draft.
- Invalid weight/date or failed persistence leaves the sheet open, preserves its draft, and announces the field/actionable error. Confirmed history remains unchanged until success.
- History rows show weight with its stored unit and readable date. Each row offers accessible `Edit weigh-in for {date}` and `Delete weigh-in for {date}` actions; icons never stand alone without labels.
- Focus returns to the invoking Add/Edit control when the sheet closes.

### Delete confirmations

- Workout deletion uses a modal confirmation titled `Delete workout?` with body `This removes the workout from {date} from this device and your synced account. This can’t be undone.` Actions: destructive `Delete workout`, safe action `Keep workout`.
- Weigh-in deletion uses title `Delete weigh-in?` with body `This removes the {weight} {unit} entry from {date} from this device and your synced account. This can’t be undone.` Actions: destructive `Delete weigh-in`, safe action `Keep weigh-in`.
- Confirmation is never triggered by expanding a row, closing an edit sheet, or saving an edit. Failed deletion keeps the record visible and shows recoverable feedback.

## State Contract

| State | History | Weight |
|-------|---------|--------|
| Loading | Preserve screen/month-card footprint with static tonal skeletons; never flash empty while local/cloud reconciliation hydrates | Preserve summary/chart/list footprint with static tonal skeletons; never display zero as a real latest weight |
| Empty | Exact empty copy and optional working Start action | Exact empty copy plus `Add weigh-in`; no empty chart axes or fabricated summary values |
| Populated | Month groups and sessions newest first; expansion exposes complete stored details | Summary, trend, add action, and newest-first history are all present |
| Partial | Malformed optional details are omitted safely; valid session content remains inspectable | One valid entry shows summary/history and chart-local partial copy; malformed entries do not crash valid content |
| Error | Isolate a malformed session/card when possible; global replacement only if no safe history can render | Isolate chart calculation failure from valid summary/history; load failure uses global error copy |
| Save failure | Edit sheet stays open with draft preserved; original session remains rendered | Add/edit sheet stays open with draft preserved; confirmed entries remain rendered |
| Delete failure | Confirmation closes only after success; otherwise record remains and retry feedback is announced | Same behavior for the weigh-in record |
| Overflow | Long month/session/exercise/note content wraps; set collections wrap; vertical page scroll only | Long dates/values/labels wrap or reflow; chart and sheet stay inside the phone column |

State transitions do not reset an unrelated expanded session, scroll position, unit selection, or confirmed record. Local state remains authoritative for immediate/offline use; cloud status is surfaced through the existing shared save/sync feedback rather than duplicating a second status system inside each card.

## Interaction Contract

- History expansion, Add, Edit, explicit discard/keep actions, Save, and Delete work equivalently with pointer, touch, keyboard, browser back, and Android back where applicable.
- Tapping a card disclosure changes only expansion state. Interactive Edit/Delete controls stop disclosure toggling and remain separately focusable.
- Edit and Add sheets reuse the focus-managed, history-aware `Sheet`: focus moves to the heading or first invalid/meaningful field, remains trapped, Escape/back/scrim/drag close when safe, and returns to the invoking control. Gesture dismissal is never the only exit.
- If the user attempts to dismiss a dirty edit draft, either retain it for the next open during the current screen lifetime or ask for confirmation; never silently overwrite the confirmed record. A clean draft closes directly.
- Save buttons remain enabled unless submission is in flight; during persistence they expose `Saving…`, prevent duplicate submission, and retain entered values. Failure produces a polite live message; destructive errors use an alert only when immediate attention is required.
- Delete requires the documented confirmation and is never undo-by-guesswork. The destructive action is visually distinct but not the default focused action.
- One-entry-per-day weight behavior is preserved. When adding for an existing date, the sheet clearly treats Save as an update rather than creating a duplicate.
- No presentation callback directly writes local storage or Firebase. Screens submit intent to `App.jsx`; only confirmed callback success changes the rendered source data.

## Accessibility Contract

- Use logical heading order: visible screen `h1`, month/major section `h2`, workout/exercise subsections below it. Do not use typography-only divs as headings.
- Month/session and weigh-in collections use semantic lists. Disclosure controls expose `aria-expanded` and target IDs; the collapsed summary remains understandable without icon or color.
- Every icon-only visual has a visible or accessible label. Chevron direction is supplemental to `aria-expanded`; day dots and chart color are supplemental to text.
- All inputs have persistent labels, described errors, and valid autocomplete/input-mode behavior. Field errors connect with `aria-describedby`; global save/delete feedback uses an appropriate live region.
- Minimum target size is 48px by 48px for disclosures, Add/Edit/Delete/Discard/Keep/Save actions, unit controls, and sheet close controls.
- The chart has a concise accessible description and a table/list equivalent; assistive users can obtain full dates, values, averages, and units without traversing every SVG mark.
- Focus is visible, follows visual order, never lands behind the fixed nav/sheet edge, and returns predictably after sheet/confirmation closure. Disabled or busy state is announced.
- Content supports 200% browser text scaling without clipping or page-level horizontal scrolling. Long exercise names, notes, validation copy, and localized dates wrap before action targets shrink.
- Light/dark text and meaningful indicators meet WCAG AA. Selection, expansion, error, and destructive state remain distinguishable without color.

## Responsive Contract

| Viewport | Contract |
|----------|----------|
| 360px phone | One column with 16px gutter; summary metadata and actions wrap; workout details and sets reflow; Weight hero values stack or use a two-column subgrid without shrinking text; sheets use full available width and safe-area padding |
| 390px phone | Same information architecture; may place compatible summary values on one row only when labels and 48px actions retain their size |
| Above 420px | Keep the phone composition centered within `.app-shell`; no tablet rail, split History detail pane, or desktop-only chart/list layout |

The page never scrolls horizontally. The weight chart uses the full inner width and responsive plotting container. If an accessible data table exceeds card width, its own labeled container may scroll horizontally; primary screen content and actions must not.

---

## Motion and Reduced Motion

- Card expansion and sheet opening use existing `--dur-med` and `--ease-emph`; button/field state changes use `--dur-short` and `--ease-std`.
- List entry stagger is optional and capped at eight items. Expanding a card does not unexpectedly scroll or move focus.
- Save success updates content in place without celebration or count-up. Weight chart updates may crossfade subtly and never replay on unrelated state changes.
- Under `prefers-reduced-motion: reduce`, disable list stagger, disclosure animation, sheet drag-settle animation, skeleton shimmer, and Recharts animation. All state changes remain immediately understandable without motion.

---

## Preservation and Non-Regression Contract

- Preserve session and weigh-in record shapes, IDs, exact local ISO dates, stored exercise names, tracking types, units, local-storage namespaces, Firestore paths, tombstones, reconciliation, backup/import, offline-first order, and sync semantics.
- Preserve current History details: day/template identity, exercises in stored order, all valid sets with tracking-specific display, notes, and existing calculated volume. Extraction may reveal other already-stored completed-record fields but cannot silently remove them.
- Preserve current Weight behavior: one entry per date, mixed stored lb/kg values, selected display unit conversion, latest/oldest net change, chronological chart, seven-day average, newest-first history, and local-first/cloud-mirror mutation ownership.
- Editing a record must be additive capability wired through `App.jsx` callbacks and established validation/persistence functions. The confirmed record cannot mutate before persistence succeeds. Date-changing edits must not leave the old cloud date behind.
- `HistoryScreen` and `WeightScreen` remain controlled presentation components. Pure normalization/grouping/chart helpers may be extracted for testing; they must not read storage, Firebase, or React state.
- Do not move export/import/reset, auth, cloud sync, or account state into these screens. Do not change Firebase rules or schemas.
- Phase 3 owns removal of broader obsolete legacy code/styles after parity. Phase 2 removes only the replaced History/Weight render blocks and their directly orphaned inline styles/helpers once the new screens are wired and verified.

## UI Considerations

Applicable state considerations resolved: 68/68 with explicit verification through the contracts above.

- **E1 — History screen shell:** Loading preserves the destination footprint without flashing empty; the documented no-workout and actionable load-error states replace only unsafe content; populated history provides the correct workout count; long state copy wraps at 200% zoom and the optional Start action retains a 48px target.
- **E2 — Month groups:** Zero sessions defer to the screen empty state; one or many sessions group by local calendar month newest-first with correct singular/plural copy; malformed dates are isolated without crashing valid groups; month labels and collections wrap/reflow without page-level horizontal overflow.
- **E3 — Workout card:** Collapsed and expanded populated states retain all valid stored details; partial optional fields are omitted rather than fabricated; malformed card content is isolated; zero/one/many exercises and sets remain legible; long names/notes wrap and set chips flow; controls remain operable during loading/save/delete states.
- **E4 — Workout edit Sheet:** A copied populated draft, partially valid draft, validation error, saving state, and persistence failure all retain form content as specified; zero/one/many exercise/set rows obey completed-workout validation; long labels/errors wrap; sheet content scrolls vertically while focus and actions remain reachable.
- **E5 — Workout delete confirmation:** The record-specific populated state, in-flight state, and failure state preserve the workout until success; long localized dates/body copy wrap; `Delete workout` and `Keep workout` retain accessible labels and targets.
- **E6 — Weight summary:** Empty/loading/error states never fabricate a latest value; one or many entries show latest, neutral signed change, count, and unit consistently; partial/malformed data does not obscure valid entries; values and labels reflow without clipping.
- **E7 — Weight trend:** Zero entries use the screen empty state, one entry uses the documented local partial state, and many entries render both supported series; calculation failure is isolated from summary/history; accessible rows cover zero/one/many valid points; labels, tooltip content, and data table handle long localized values with contained overflow only.
- **E8 — Weigh-in history:** Empty defers to the documented Weight state; one or many entries render newest-first with correct units and dates; malformed entries are filtered or isolated without crashing valid rows; in-flight mutation preserves confirmed rows; long values/labels wrap before action controls shrink.
- **E9 — Add/edit weigh-in Sheet:** Empty add form and populated copied edit form support partial input, validation, saving, and failure without losing the draft; existing-date update behavior is explicit; field labels/errors wrap; vertical Sheet scrolling preserves access to Save and the noun-bearing Close/Discard action with focus handling.
- **E10 — Weigh-in delete confirmation:** Record-specific content, deletion in flight, and failure retain the confirmed entry until success; long values/dates wrap; `Delete weigh-in` and `Keep weigh-in` remain distinct, labeled, and keyboard/touch accessible.
